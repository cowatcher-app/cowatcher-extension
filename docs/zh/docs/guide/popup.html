Netflix AI Subtitle Translator - 控制面板 (Popup UI) 详细使用指南 ​

本文档全面介绍 Netflix AI Subtitle Translator 扩展控制面板（Popup 弹窗）中各项功能、UI 控件的用途、推荐配置以及调优技巧。

目录 ​

  1. 顶部状态栏与主开关
  2. AI 服务提供商配置 (Ollama 与 OpenRouter)
  3. 语言与字幕显示偏好
  4. 影视记忆与角色表管理 (Show Context)
  5. 双模型流水线性能调优 (Pipeline Settings)
  6. 字幕视觉样式与时间轴微调
  7. 快速连通性与模型测试 (Quick Test)

1. 顶部状态栏与主开关 ​

1.1 全局启用开关 (#enabled-toggle) ​

  • 位置：右上角切换开关。
  • 功能：全局启用或禁用 AI 字幕翻译。
  • 说明：
    • 开启（绿色）：在 Netflix 播放页面自动监听字幕流并实时渲染翻译。
    • 关闭：隐藏 AI 字幕并暂停所有后台模型推理，同时恢复 Netflix 原始字幕层。
    • 快捷键：播放页面随时按下 Alt + T 可实现相同开关效果。

1.2 Ko-fi 赞助按钮 (☕) ​

  • 位置：顶部右上角与弹窗底部。
  • 功能：点击在新标签页打开作者的 Ko-fi 赞助页面。

1.3 服务连接状态卡片 (#status-card) ​

  • 状态指示灯：
    • 🟢 绿色 (Connected)：服务连通正常，模型列表已成功加载。
    • 🟡 黄色 (Checking / Warning)：正在检测连通性或未配置有效模型。
    • 🔴 红色 (Disconnected / Error)：无法连接到本地 Ollama 或云端 API 认证失败。
  • 刷新按钮 (🔄)：手动重新向当前服务提供商发送探测请求，重新拉取最新可用的模型列表。

2. AI 服务提供商配置 ​

在 🤖 AI Service Provider (#ai-provider) 下拉框中，您可以自由切换两种推理模式：

2.1 本地部署：Ollama (Local / Privacy-first) ​

适合拥有独立显卡（如 NVIDIA RTX 3060 及以上）、注重隐私且无需消耗云端 Token 的用户。

控件名称元素 ID推荐值 / 示例说明
Ollama API URL#ollama-hosthttp://localhost:11434本地或局域网 Ollama 服务的监听地址。点击 Connect 按钮测试连接并更新模型列表。
翻译模型 (Translation Model)#translation-modeltranslategemma:4b负责快速批量翻译（默认预翻译 50 句）。系统会自动从本地 ollama list 中读取所有已拉取的模型。
监督模型 (Supervisor Model)#supervisor-modelgemma4:e4b负责剧集背景预热、术语统一审校与人名记忆提炼。建议选择指令理解能力更强的模型。

提示：如果在 Linux/macOS 下遇到跨域错误，启动 Ollama 时可添加环境变量 OLLAMA_ORIGINS="*" ollama serve。

2.2 云端平台：OpenRouter (Cloud / Multi-model) ​

适合轻薄本、核显用户，或者追求前沿大模型极高质量翻译（如 DeepSeek V3、Gemini 2.5 Pro、Claude 3.5 Haiku 等）的用户。

控件名称元素 ID推荐值 / 示例说明
OpenRouter API Key#openrouter-api-keysk-or-v1-...您的 OpenRouter API 密钥。可点击右侧 👁️ 图标明文查看或隐藏，点击 Connect 进行鉴权。密钥安全保存在本地浏览器存储中，绝不上传到任何第三方。
OpenRouter 翻译模型#openrouter-translation-modeldeepseek/deepseek-chat 或 google/gemini-2.5-flash下拉框内置了高性价比推荐模型列表，并在连接后动态拉取 OpenRouter 的完整模型库。
自定义翻译模型 ID#openrouter-custom-translation-model如 qwen/qwen-2.5-72b-instruct在下拉框选择「✏️ 自定义输入模型 ID」时出现，支持填入 OpenRouter 支持的任意模型标识符。
OpenRouter 监督模型#openrouter-supervisor-modelgoogle/gemini-2.5-flash 或 deepseek/deepseek-chat负责多批次审阅与人物角色表维护。云端并发度高、处理长文本能力极佳。
自定义监督模型 ID#openrouter-custom-supervisor-model如 google/gemini-2.5-pro在下拉框选择「✏️ 自定义输入模型 ID」时出现。

2.3 监督模型全局开关 (#enable-supervisor) ​

  • 功能：是否启用第二模型进行影视背景维护与人名一致性校对。
  • 开启建议：
    • 看剧情片、动漫（人名昵称复杂）、连续剧时强烈建议开启，能彻底解决角色前几集叫“小翔”、后几集变“硝子”等称呼混乱问题。
  • 关闭建议：
    • 本地显存不足（如只有 4G~6G VRAM）时，关闭可避免双模型在显存中进出置换；
    • 使用 OpenRouter 时若想进一步节省 Token 费用，也可将其关闭。

3. 语言与字幕显示偏好 ​

3.1 界面语言 (#ui-language) ​

  • 支持 English、中文 (Chinese)、日本語 (Japanese)、한국어 (Korean)。
  • 切换后立刻实时更新插件界面的全部文本与提示信息。

3.2 翻译目标语言 (#target-language) ​

  • 支持 15 种主流语言（简体中文、繁體中文、English、日本語、한국어、Español 等）。
  • 语言隔离机制：切换目标语言时，插件会自动切换至对应语言的影视记忆与角色字典（例如《Stranger Things》的中文记忆与日文记忆独立存储，互不干扰）。

3.3 字幕显示模式 (#display-mode) ​

  1. 双语模式 (Bilingual)：上方显示翻译语言，下方显示原声字幕（默认推荐）。
  2. 仅显示翻译 (Translation Only)：画面只呈现 AI 翻译结果，纯净观影。
  3. 仅显示原声 (Original Only)：只显示经过插件排版优化的原声音轨字幕。

3.4 隐藏 Netflix 原生字幕 (#hide-native-subs) ​

  • 默认状态：开启（推荐）。
  • 原理：通过 CSS 将 Netflix 原生自带的字幕渲染层透明化，防止原生单语字幕与 AI 双语字幕在屏幕中央产生重影或重叠，同时完全不影响底层网络字幕流的捕获。

4. 影视记忆与角色表管理 ​

在 🎬 Show Context & Supervisor Memory 卡片中，展示了当前播放影片的上下文积累情况：

  • 作品标题 (#show-title)：自动提取正在播放的影视剧名称与季度信息。
  • 记忆状态标签 (#memory-badge)：
    • Pending：等待播放开始。
    • Ready：背景预热完成，角色表建立完毕。
    • Auditing：监督模型正在后台审阅新字幕批次。
  • 剧情梗概 (#show-synopsis)：由监督模型在背景预热阶段自动生成的剧集背景简介。
  • 角色与术语标签栏 (#glossary-tags)：
    • 实时展示当前剧集已收录的专有名词与角色别名映射（如 Shou-chan ➔ 西宫硝子）。
    • 每个标签右侧带有 × 按钮，点击可立即移除该映射。
  • 手动添加/纠正词条 (#input-term-orig ➔ #input-term-trans)：
    • 如发现某位主角名字翻译不符合个人喜好，可在输入框填入原文名字（如 Eleven）与目标翻译（如 小十一），点击 Save，即可强制锁定全局翻译规则。
  • 重置记忆按钮 (#btn-reset-context)：
    • 清空当前作品累积的角色表与背景记忆，并在下一次播放时重新触发 Warmup（预热）。

5. 双模型流水线性能调优 ​

插件内置了针对 Ollama（本地算力） 与 OpenRouter（云端算力） 的独立预设参数，并支持用户自定义拖拽微调：

5.1 动态 Cue 批量与缓冲参数 ​

① 最小请求句数 (min_cue / #min-translate-cues) ​

  • 滑块范围：1 ~ 20 句（默认：1 句）。
  • 机制原理：当缓冲区字幕达到该数量时，即可触发一次模型推理下发。设置为 1 可确保任何新出现的零散字幕立即开始翻译。
  • 空仓急冲 (Seek Burst)：当用户拖动进度条跳转到未翻译的片段时，系统自动采用 Math.max(min_cue, 6) 下发首批请求，确保 400ms 内瞬间上屏首句字幕，同时立刻构建起最少 6 句的初始安全缓冲，彻底消除卡顿。
  • 片尾免截断 (Tail Exemption)：在影视剧末尾或原始字幕轨尾部时，系统会自动解除 min_cue 门槛限制。即使剩余未翻译的台词不足设定句数，也会全量下发翻译，彻底避免片尾最后几句台词被遗漏或截断。

② 单次最大下发句数 (max_cue / #max-translate-cues) ​

  • 滑块范围：10 ~ 150 句。
  • 预设配置：
    • Ollama 预设：30 句（防止本地轻量模型单次长文本输出丢行或显存占用过高）。
    • OpenRouter 预设：100 句（充分利用云端大模型的高并发与长上下文处理能力，减少网络往返耗时）。

③ 自动补充阈值 (refill_threshold / #refill-threshold) ​

  • 滑块范围：2 ~ 40 句。
  • 预设配置：Ollama 预设 10 句；OpenRouter 预设 20 句。
  • 说明：当播放器中剩余未播放的预翻译字幕低于该阈值时，后台静默自动拉取下一批字幕，确保在持续观影过程中永远不会出现字幕“断供”。

5.2 监督模型审校批次大小 (reviewBatchSize / #review-batch-size) ​

  • 滑块范围：2 ~ 40 句。
  • 预设配置：Ollama 预设 8 句；OpenRouter 预设 20 句。
  • 说明：监督模型每次在单个 Prompt 中集中比对的对话数量。云端模型可适当调大（如 20 句），效率更高且上下文关联性更强。

6. 字幕视觉样式与时间轴微调 ​

6.1 视觉样式调整 ​

  • 字幕字体大小 (#font-size)：范围 18px ~ 44px（默认 26px）。
  • 字幕背景透明度 (#bg-opacity)：范围 0% ~ 100%（默认 0% 全透明）。在画面背景非常花哨时，可适当调至 30%~50% 提高对比度。
  • 底边距 (#sub-offset)：范围 40px ~ 180px（默认 80px），微调字幕距离屏幕底部的悬浮高度，避免遮挡原生进度条。
  • 原文字幕缩小显示 (#show-original-smaller)：开启后双语模式中的原声语言按 75% 字号显示，突出主翻译语言。
  • 毛玻璃效果底框 (#enable-glass-effect)：启用半透明高斯模糊背景与细腻边框，呈现高端磨砂质感。
  • 字幕淡入淡出动画 (#enable-animation)：
    • 默认关闭：字幕瞬间切换，0 延迟、0 闪烁，字字清晰干脆。
    • 开启：呈现温和平滑的渐隐渐现视觉动效。

6.2 时间轴偏移校准 (#sync-offset-val) ​

当遇到含广告套餐中插广告、或者片源音画不同步时：

  • 点击 Earlier (+0.5s)：字幕提前 0.5 秒呈现（快捷键：[ 或 Alt + [）。
  • 点击 Later (-0.5s)：字幕延后 0.5 秒呈现（快捷键：] 或 Alt + ]）。
  • 点击 Reset：重置偏移量为 0.0 秒（快捷键：\ 或 Alt + \）。
  • DOM 原生字幕自动校准 (#enable-dom-sync)：
    • 默认关闭。当开启时，插件会比对 Netflix 屏幕可见的原生字幕字符变化来微调时间，常规播放时无需开启（播放器内核 API 已自动高精对齐）。

7. 快速连通性与模型测试 ​

在 Quick Test 区域，您可以在不打开 Netflix 播放页面的情况下，直接验证当前模型配置是否工作正常：

  1. 在文本框输入任意测试对话（如 Hello! The weather is fantastic today.）。
  2. 点击 Test 按钮。
  3. 第一阶段：翻译模型下发并返回目标语言译文，展示本次翻译耗时（毫秒）。
  4. 第二阶段：如果启用了监督模型，系统紧接着模拟监督审阅流程，并在下方展示监督模型修正结果与耗时。

8. 常见问题与调优建议 ​

Q1: 本地 Ollama 响应较慢导致字幕跟不上？ ​

  1. 换用高速度小模型：翻译模型推荐 translategemma:4b 或 qwen2.5:3b。
  2. 调大提前量与阈值：将 max_cue 调整至 40，将 Auto-Refill Threshold 调整至 15，让模型更早地在后台完成预处理。
  3. 关闭监督模型：在显存或 CPU 负载较高时，关闭 #enable-supervisor。

Q2: 想使用云端顶尖模型，如何兼顾速度与成本？ ​

  • 服务提供商选择 OpenRouter：
    • 翻译模型：选择 deepseek/deepseek-chat（极其便宜且翻译质量顶尖）或 google/gemini-2.5-flash（速度极快）。
    • 监督模型：选择 google/gemini-2.5-flash。
    • Pipeline 设置：直接使用系统默认预设（max_cue = 100，review_batch = 20），网络吞吐最高，每集观影成本微乎其微。
